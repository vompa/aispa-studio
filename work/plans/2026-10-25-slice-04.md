# Slice 04 – Meldungen und Primärknöpfe in Sicherung, Abgleich und Geräten: Umsetzungsplan

> **Für ausführende Agenten:** Pflicht-Skill superpowers:subagent-driven-development (empfohlen) oder superpowers:executing-plans; Schritte als Kästchen (`- [ ]`). **Alle Prüfungen im Vordergrund**, keine Hintergrundbefehle.

**Ziel:** Sicherung, Abgleich, Geräte und Verwaltung zeigen Meldungen als `ui:InfoBar` (Warnung in Warnfarbe mit Symbol, nie rote Schrift), Statuszeilen werden höflich angesagt, und jede dieser Seiten hat genau einen sichtbaren Primärknopf.

**Architektur:** Die vorhandene `InfoBar` (`src/AispaStudio.Desktop/Controls/InfoBar.cs:23`) ersetzt jedes `Border Classes="alert"` in BackupView, SyncView, DevicesView und AdminView. Für die beiden Warnungen mit einmal angezeigtem Code (Wiederherstellungsschlüssel, Schlüsselcode) bekommt die InfoBar eine optionale Eigenschaft `Detail` (beliebiger Inhalt unter dem Text), damit der Code in der Warnung steht und nicht lose darunter. Felder des Abgleichs bekommen `ui:FormField`.

**Technik:** Avalonia 12, CommunityToolkit.Mvvm, xUnit mit Avalonia Headless (vorhanden), keine neuen Pakete.

**Spezifikation:** `work/slices/04-app-messages-settings.md`; Befunde W10, W11, W13, W16, W17, W-Muster 2, 3, 4, 13 in `docs/umsetzung/aenderungsliste-oberflaechen-2026-10-23.md`; Regeln `docs/gestaltung/meldungen.md`, `docs/gestaltung/masken.md`, Brief 5.1, 5.9, 5.15.

## Annahmen (bei Freigabe bestätigen)
1. **InfoBar bekommt `Detail`** (`object?`, unter Titel und Text in derselben Spalte, ohne Inhalt unsichtbar). Der Code bleibt dadurch in der Warnung, markierbar, 22 px Consolas. Alternative wäre der Code lose unter der InfoBar (wie die Liste in Slice 03); verworfen, weil der Code zur Warnung gehört. Slice 05 kann `Detail` mitnutzen.
2. **Schlüssel-Warnung der Sicherung:** `Severity="Warning"`, Titel „Wiederherstellungsschlüssel notieren“, Text „Ohne diesen Schlüssel sind die Gesundheitsdaten einer Sicherung auf einem anderen PC nicht lesbar, und er setzt vergessene Passwörter zurück. Ausdrucken oder aufschreiben und bei der Leitung aufbewahren, getrennt vom PC. Die App zeigt ihn nur jetzt.“ (gekürzt, „Bitte“ entfällt), `Detail` = Code plus das bisherige Fragezeichen (`HelpButton sicherung/wiederherstellungsschluessel`), Aktion „Verstanden“ → `CodeNotedCommand`, kein Schließen-Kreuz.
3. **Schlüsselcode im Abgleich:** `Severity="Warning"`, Titel „Schlüsselcode notieren“, Text „Jede weitere Stelle braucht ihn beim Verbinden. Sicher aufbewahren.“, `Detail` = Code, Aktion „Verstanden“ → `CodeNotedCommand`.
4. **Schweregrade:** Sicherung `ErrorText`, Geräte `DeviceError`, Verwaltung `Error` → `Error`; Abgleich `ErrorText` (wiederholt sich jede Minute) und Geräte `Agent.Status` → `Warning`. Verwaltung: Titel „Verwaltung nicht erreichbar“, Aktion „Erneut versuchen“ → `CheckCommand`.
5. **Felder:** Abgleich `ui:FormField Label="Verbindungsangabe"` um :72 und `Label="Schlüsselcode des Spas"` um :76; die langen Erklärtexte bleiben als Absätze darüber (zu lang für `Help`). Sicherung :59 bekommt `AutomationProperties.Name="Sicherungsordner"` statt FormField, weil die Karte schon „Ordner“ als Überschrift trägt.
6. **Ein Primärknopf je Seite:** Sicherung und Abgleich durch die InfoBar-Aktion (kein `primary`); Geräte: „Diesen PC als Empfangsgerät anmelden“ wird sekundär (ohne Klasse), „Speichern“ bleibt primär.
7. **Statuszeilen** Backup :45, Sync :94, Devices :38, :92, :100 behalten ihr Aussehen und bekommen `AutomationProperties.LiveSetting="Polite"` (kein Toast; der Befund nennt das als Mindestmaß).
8. **Hilfe:** die drei Hilfestellen sprechen von „der Warnung“ und „Verstanden“ statt „gelber Kasten“ und „Notiert“; das Beispiel in `texte.md` zieht mit. Neues Bild nur `sicherung.png`; kein ADR.

## Review-Fokus
1. Sichtbarkeit: jede InfoBar übernimmt genau die bisherige `IsVisible`-Bedingung (Geräte mit `Agent?.NeedsAttention, TargetNullValue=False`).
2. Code in `Detail` bleibt markierbar und wird nicht abgeschnitten (Umbruch der Textspalte, Breite 720).
3. Screenreader-Name der InfoBar bleibt „Titel: Text“, der Code ist als eigenes Element erreichbar.
4. Nach „Verstanden“ verschwindet die Warnung und „Speichern und sichern“ bleibt der einzige Primärknopf.
5. Dunkles Design: Warnfarben aus den vorhandenen `Border.infobar.warn`-Stilen, keine roten Texte.
