# Slice 14 – Rückfragen im Web: Fokus auf Abbrechen, Dienstplan fragt vor dem Verwerfen: Umsetzungsplan

> **Für ausführende Agenten:** Pflicht-Skill superpowers:subagent-driven-development (empfohlen) oder superpowers:executing-plans; Schritte als Kästchen (`- [ ]`).

**Ziel:** In den fünf Rückfragen der Verwaltung („Schließzeit löschen?“, „Raumsperre löschen?“, „Aktion archivieren?“, „Abo löschen?“, „Eintrag archivieren?“) liegt der Fokus nach dem Öffnen auf „Abbrechen“, und „Verwerfen“ im Dienstplan fragt mit der Zahl der Entwürfe zurück, bevor es die Entwürfe wegwirft.

**Architektur:** Ursache von B1: React-`autoFocus` ruft `focus()` beim Einhängen, der `<dialog>` ist da noch zu; `showModal()` im Effekt danach fokussiert den ersten Knopf, und das ist die Aktion. Jeder der fünf Dialoge bekommt eine `ref` auf „Abbrechen“ und setzt den Fokus im selben Effekt **nach** `showModal()`; `autoFocus` entfällt. jsdom 29 kennt `showModal()` nicht: im Test läuft heute der Zweig `setAttribute('open', '')`, und Reacts `focus()` wirkt sofort, deshalb sind die zwei bestehenden Fokus-Prüfungen grün, obwohl der Browser den Fehler zeigt. Eine Vitest-Setup-Datei gibt jsdom ein `showModal()`, das sich wie der Browser verhält (öffnen, dann Fokus auf das `autofocus`-Element, sonst auf den ersten fokussierbaren Nachfahren); damit zeigen die Tests den Fehler und die Behebung. B47: `RosterPage` bekommt den Zustand `discarding` und einen eigenen `DiscardDraftsDialog` nach dem Muster `DeleteDialog` aus `web/src/closures/ClosuresPage.tsx:527-551` (kein gemeinsamer Baustein, B2 ist offen).

**Technik:** React 19, TypeScript, Vitest 5 mit jsdom 29 und Testing Library (vorhanden); keine neuen Pakete. `playwright-core` liegt nur für die Hilfebilder im Repository (`web/scripts/help-images.mjs`), ein Testlauf im Browser bräuchte `@vitest/browser` oder `@playwright/test` – deshalb der Weg über die Setup-Datei.

**Spezifikation:** `work/slices/14-web-confirm-focus.md`, Befunde B1 und B47 in `docs/umsetzung/aenderungsliste-oberflaechen-2026-10-23.md`, Brief `docs/design.md` 5.27 (Rückfragedialog), `docs/gestaltung/texte.md`.

```ts
// web/src/vitest.setup.ts
// jsdom kennt showModal() nicht. Der Ersatz öffnet den Dialog und setzt den Fokus wie der Browser (Fokussierschritte
// des Dialogs): auf das Element mit autofocus, sonst auf den ersten fokussierbaren Nachfahren.
const focusable = 'button:not([disabled]), [href], input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])'
if (typeof HTMLDialogElement !== 'undefined' && typeof HTMLDialogElement.prototype.showModal !== 'function') {
  HTMLDialogElement.prototype.showModal = function showModal(this: HTMLDialogElement) {
    this.setAttribute('open', '')
    const target = this.querySelector<HTMLElement>('[autofocus]') ?? this.querySelector<HTMLElement>(focusable)
    target?.focus()
  }
}
```
